# 16 种版式

每张卡是 `{ "layout": "...", "text": "...", "figure": { "source": "none|ready|yours|draw", "note": "..." } }`。`text` 的写法因版式而不同；字数按字符算（一个汉字、一个字母、一个标点都算 1）。超过上限只是提醒，文字超出卡片才报错。

「结构化」版式（窗口截图到清单、图表这 10 种）按行格式画成固定结构，内容少时字号会自动放大（最多 1.6 倍）填满页面。其余版式按 Markdown 排，短文案自动用大字。

## cover 封面

- 用途：只用于第 1 张，封面大字，抓住要点或动机。
- 写法：一句话。也可以在 cards.json 顶层写 `covers` 出 2–3 个备选。
- 上限：≤16 字（超过 24 字就不当封面，会按一句话排）。
- 示例：`先出分镜，再出图`

## statement 一句话

- 用途：一个观点或结论。
- 写法：一段话。
- 上限：≤40 字。
- 示例：`一组图只让人带走一句话，每页都为它服务。`

## list 要点

- 用途：3–5 条并列的要点。
- 写法：每条一行，以「- 」开头。
- 上限：3–5 行，每条 ≤18 字。
- 示例：
  ```
  - 先定带走点
  - 一页只讲一件事
  - 数字照抄原文
  ```

## steps 步骤

- 用途：有先后顺序的 3–5 步。
- 写法：每步一行，以「1. 」「2. 」开头。
- 上限：3–5 行，每步 ≤18 字。
- 示例：
  ```
  1. 读材料
  2. 出分镜表
  3. 确认后出图
  ```

## compare 对比表

- 用途：两边对比（以前 vs 现在、A vs B）。
- 写法：两列 Markdown 表格。第一行表头，第二行 `| --- | --- |`（漏写会自动补）。
- 上限：内容最多 4 行，每格 ≤10 字。
- 示例：
  ```
  | 以前 | 现在 |
  | --- | --- |
  | 直接排版 | 先出分镜 |
  | 出完才发现缺图 | 出图前就拦下 |
  ```

## window 窗口截图

- 用途：电脑软件或网页的真实截图，放进窗口框。
- 写法：`![说明](相对路径.png)` 加一句说明。`figure` 必须是 `ready` 或 `yours`。
- 上限：说明 ≤30 字。
- 示例：`![设置页](shots/settings.png)\n设置里打开这个开关`

## phone 手机截图

- 用途：手机界面的真实截图，放进手机框，说明放旁边。
- 写法：同 window。
- 上限：说明 ≤30 字。
- 示例：`![通知](shots/notice.png)\n推送会在这里出现`

## code 代码

- 用途：一段代码或命令，放进编辑器框，带行号。
- 写法：第一行可以写「文件：文件名」，其余原样写代码（外面包 ``` 也行）。
- 上限：≤12 行，每行 ≤40 个字符。
- 示例：
  ```
  文件：终端
  node scripts/render.mjs cards.json
  ```

## prompt 提示词

- 用途：一段读者可以直接复制去用的提示词，放进输入框。
- 写法：提示词原文。
- 上限：≤120 字。
- 示例：`把下面这篇文章拆成 6 页小红书分镜，每页只讲一件事，先给我看分镜表。`

## chat 对话

- 用途：一问一答。
- 写法：每行以「问：」或「答：」开头（也认 Q: / A:），没有前缀的行接在上一句后面。
- 上限：2–4 行，每行 ≤40 字。
- 示例：
  ```
  问：没有截图怎么办？
  答：标成 yours，没给图就拦下。
  ```

## metric 数据

- 用途：1–3 个关键数字，大字显示。
- 写法：每行「数字｜单位｜说明」（全角｜或半角|都行）。
- 上限：1–3 行，说明 ≤12 字。数字必须在原文里出现。
- 示例：
  ```
  15｜种｜版式
  2｜套｜外观
  ```

## rightwrong 对错

- 用途：对的做法和错的做法并排。
- 写法：每行以「✓ 」或「✗ 」开头。
- 上限：2–4 行，每行 ≤20 字。
- 示例：
  ```
  ✓ 数字照抄原文
  ✗ 编一张截图凑数
  ```

## timeline 时间线

- 用途：按时间或先后发生的 3–5 件事。
- 写法：每行「时间｜事件」。
- 上限：3–5 行，事件 ≤18 字。
- 示例：
  ```
  上午｜读材料，定带走点
  下午｜确认分镜，出图
  ```

## checklist 清单

- 用途：可以照着打勾的清单。
- 写法：每行以「[x] 」（已做到）或「[ ] 」（要去做）开头。
- 上限：3–5 行，每行 ≤18 字。
- 示例：
  ```
  [x] 文字没有超出卡片
  [ ] 补上后台截图
  ```

## chart 图表

- 用途：把原文里真有的数据或结构画成图（`figure` 写 `draw`，即代码画）。脚本用自己的代码画成 SVG，不用图表库，也不执行模型写的代码。只画原文里有的东西，不画装饰图；凑不出真实数据就换别的版式。
- 写法：第一行写图的类型，可以带标题（「柱状：冷启动耗时」），下面每行一项：

  | 类型 | 什么时候用 | 每行写法 | 项数 |
  |---|---|---|---|
  | `柱状` | 几项比大小 | 「名称｜数值」 | 2–8 |
  | `折线` | 同一个量随时间或版本变化 | 「名称｜数值」 | 2–8 |
  | `环形` | 几部分占整体 | 「名称｜数值」，数值大于 0 | 2–6 |
  | `流程` | 有先后的步骤 | 一步一行，可在后面写「→ 说明」 | 2–6 |
  | `对比` | 两边对照 | 「左｜右」，第一行是两边的名字 | 1–6 行 |
  | `矩阵` | 2×2 四象限 | 前两行「横轴：…」「纵轴：…」，再四行「象限名｜内容」（左上、右上、左下、右下） | 4 |
  | `时间轴` | 按时间发生的事 | 「时间｜事件」 | 2–6 |

- 数值照原文写（「1.2 秒」「45%」「3x」都行），图上原样显示，不换算、不四舍五入；柱长、折线高低按其中的第一个数字画；时间可以混写单位（「0.082s」「8m30s」「120ms」都按秒比较），其它单位不一致（比如一项是 MB、一项是秒）会报错。不画坐标刻度（刻度会是原文里没有的数）。所有项单位相同时，第二行可以写「单位：秒」。要突出的那项放第一行（柱状、环形用满色）。
- 上限：建议名称、每格、每步 ≤14 字，事件 ≤18 字（超出卡片才报错）。格式不对（类型不认识、少了数值、矩阵不是 4 格、项数不在范围内）会报错不出图；提供了原文时，图里的每个数字（包括标题、名称里的）都要在原文里找到。
- 颜色只用卡片的主色、正文色、辅助色和分隔线色，跟着外观和 `accent` 走；内容少时和其它结构化版式一样自动放大。
- 示例：
  ```
  环形：16 种版式怎么排
  按行格式画成固定结构｜10 种
  按 Markdown 排｜6 种
  ```
  ```
  流程：从材料到出图
  读材料 → 定一句带走点
  出分镜 → 等你确认
  写 cards.json
  渲染出图 → 报错就改，再跑
  ```

## ending 结尾

- 用途：只用于最后一张。总结，或一个引导互动的问题；定了互动动机时必须是问题（带「？」）。
- 写法：一句话。
- 上限：≤40 字。
- 示例：`你手上哪篇笔记，最想先做成图？`

## 配图 figure

| source | 意思 | text 里 |
|---|---|---|
| `none` | 不配图 | 不写图 |
| `ready` | 用现成的图（原文里已有、或用户已经给了） | 写 `![说明](相对路径)` |
| `yours` | 只有作者本人能给的真实截图或照片 | 拿到图之前不写图；`note` 写清要截哪个界面、哪一步（≤30 字） |
| `draw` | 代码画：脚本照 `text` 画的图表，只配 `chart` 版式 | 图表的行格式（见上面 chart）；`note` 写这张图画的是什么 |

`yours` 没给图、window / phone 没有图、文字里还有「待补」，都会报错不出图。
